## 2. 实测：哪种答案格式会被认出来（关键证据）

我把各种"模型可能输出的格式"直接喂给本项目真正使用的 resolver。

### 2.1 判断题（正确答案 = `错误`）

| 模型输出 | resolver 结果 |
|---|---|
| `错误` | ✅ 命中 |
| `False` / `×` / `错` / `不正确` | ✅ 命中 |
| **`错误。`** | ❌ **失败** |
| **`错误（该说法不成立）`** | ❌ **失败** |

机制：`resolveJudgement` 把答案与极性词做**清理标点后完全相等**比较，**不做包含匹配**。
→ 模型只要多写一个句号或一句补充，这题就判"答不出"。

### 2.2 单选（正确答案 = `A. 信念的证成`）

| 模型输出 | 结果 |
|---|---|
| `A. 信念的证成` / `信念的证成` / `A` | ✅ 命中 A |
| `这道题应该选 A. 信念的证成` | ✅ 命中 A（包含式，合理） |
| **`a`（小写）** | ❌ 失败 |
| **`信念的证明`（错一个字）** | ⚠️ **命中 A，rating 0.75** —— 相似匹配强行命中 |

→ 好的一面：模型只要**照抄选项文字**就稳。
→ 坏的一面：**措辞走样不会报错**，而是静默挑"最像"的选项，可能是错的（P3）。

### 2.3 多选（正确答案 = `A. 基础主义` + `C. 可靠主义`）——**格式不是问题**

| 模型输出 | 结果 |
|---|---|
| `基础主义,可靠主义`（英文逗号） | ✅ A、C |
| `基础主义、可靠主义`（顿号） | ✅ A、C |
| `A,C` / `AC` / `A.C.` | ✅ A、C |

> 我原本怀疑"提示词让模型用逗号，而 `splitAnswer` 不认逗号"——**实测这个怀疑不成立**：
> 多选走的是"包含式"匹配，未切分的整串里包含各选项文字即可命中。**多选题不是主要失分点。**

### 2.4 填空（关键冲突）🔴

`resolveCompletion` 的硬条件是：**答案段数必须等于空数**

```ts
if (ans.length !== 0 && (ans.length === blankCount || blankCount === 1)) { ... }
```

而 `splitAnswer` 的默认分隔符是：

```
['===', '#', '---', '###', '|', ';', '；']     ← 不含换行、不含逗号、不含顿号
```

我们的提示词却要求多空题输出：

```
第1空：单精度型
第2空：双精度型
```

→ **换行不被切分** → 段数 = 1 ≠ 空数 2 → **整题判失败** ✅

**只有单空题（`blankCount === 1`）能过**。多空填空是系统性失分点。

## 3. 为什么"看起来正确率很低"

三个机制叠加：

1. **匹配失败 → 随机兜底**（`cxRandomFallback` 默认 `true`）
   → 填一个随机选项，界面上还显示"已作答"，**外观正常、结果错**（P2）
2. **缓存复用**：若开启了答题缓存，随机/错误答案会被缓存，**下次同题直接复用错答案**（P5）
3. **匹配失败 → 留空**：作业/考试没有随机兜底时，题目直接空着 → 分数低

## 4. 提示词层面的问题（与 DeepSeek 网页版差距的根源）

对比两种使用方式：

| | DeepSeek 网页版 | 本脚本 |
|---|---|---|
| 输出 | 一段推理 + 答案 | **只有答案**（提示词第 1 条禁止解释） |
| 谁来"理解"输出 | **人**（能容错、能看推理） | **resolver**（严格匹配，不容错） |
| 复杂题的容错 | 高 | **极低** |

具体提示词缺陷：

1. **判断题没限制"只输出两个词，不要标点"** → 实测 `错误。` 就失败
2. **单选/多选没要求"逐字照抄选项原文，不要改写/翻译/加标点"** → 走样后靠相似匹配硬凑（可能错）
3. **多空填空要求的「第N空：」格式与 resolver 的分隔符不兼容**（§2.4）
4. 复杂题强行"一句话答案"，压缩掉了必要限定语（如"以上都对""均为"）→ 更容易走样

> 注意：**提示词本身不是"模型答错"的原因**，而是**模型输出无法被脚本识别**的原因。
> 这解释了"同样用 DeepSeek，网页版看着准、脚本看着不准"。

## 8. 补充实验：10 道线性代数题（2026-10-25，用真实 Key 实测）

用户指出"只看文科题过于局限"，并提供 10 道线性代数题截图。题目与标准答案
（人工核算）见 `tools/math-bench-questions.json`，评测脚本见 `tools/math-bench.mjs`。

### 8.1 干净输入（理想情况）

| 提示词 | 答对率 | 纯字母输出 |
|---|---|---|
| 旧版（输出选项全文） | **10/10 = 100%** | 0/10 |
| 只输出字母 | 10/10 = 100% | 10/10 |
| 允许简短推导 | 10/10 = 100% | 0/10 |

**结论：模型的"分析能力"没问题** —— 干净输入下三种提示词都 10/10。
所以问题不在"模型不会算"，而在**输入/输出链路**。

### 8.2 模拟真实页面（公式选项被 MathJax/图片提取成残片）

| 提示词 | 答对率 |
|---|---|
| **旧版（输出选项全文）** | **4/10 = 40%** 🔴 |
| **只输出字母** | **9/10 = 90%** ✅ |

失败模式（旧版）：模型输出**完全正确的答案**，但脚本
- Q4 `(5,1,-1,2)^T` → **未识别**
- Q7 `k(α1-α2)` → **未识别**
- Q5/Q9 正确选项原文 → 被判成 **B**（静默错配）
- Q10 → 被判成 **A**（与截图上"我的答案:A 正确答案:B"一致）

**根因：线性代数选项彼此极像（差一个符号/顺序/系数），
"输出选项全文 + 相似匹配"会挑错，而且不报错。**

### 8.3 已落地的修改（版本 5.2.1-cxstudy.5）

1. **提示词**：单选/多选改为**只输出字母**（多选 `A,C`）；禁止任何前缀（答案：/选/应该选）；
   判断题明确"不要加句号、不要补充说明"
2. **响应归一化**（防御性）：自动处理 `a`→`A`、`A、C`→`A,C`、`(B)`→`B`、
   `答案：C`→`C`、`应该选 D`→`D`、`C. 语言的指称`→`C`、`错误。`→`错误`、
   `错误（该说法不成立）`→`错误`、`不正确`→`错误`
3. **防误伤**：填空题的 `AC`/`BD` 这类缩写**不会被**改成 `A,C`
   （仅"单字母 / 原文含分隔符 / 剥离过前缀"才收敛；且 resolver 本身有 ABCD 兜底）

### 8.4 回归验证（改前 vs 改后，选项扰动场景）

```
旧版（输出选项全文）   4/10 = 40%
当前发货版（只输出字母） 9/10 = 90%     ← +50 个百分点
```

产物：`5.2.1-cxstudy.5`，487,514 bytes；测试 164 + 68 + 20 + 30 = **282 项全绿**。

## 9. 事故复盘：v5 的归一化把填空题弄坏了（v6 已修）

用户反馈：升级到 `5.2.1-cxstudy.5` 后**填空题无法正常写入**，而上一版可以。

### 9.1 根因：归一化写得太宽

v5 引入的"答案归一化"为了实现"只输出字母"，用了**很宽的前缀剥离 + 字母抽取**，
在填空题上误伤。用 26 个真实填空答案做旧/新差分，**7 处被改写**：

| 填空答案 | v5 输出 | 后果 |
|---|---|---|
| `A、B 两点间距离` | `A` | **答案被截断** |
| `选项一` | `一` | **前缀误剥** |
| `选择最优解` | `择最优解` | **前缀误剥** |
| `该说法错误` | `错误` | 被当成判断题 |
| `a` | `A` | 变量名被大写 |
| `(A)` | `A` | 括号丢失 |
| `答：2x+1` | `2x+1` | （这个是对的）|

### 9.2 另一个隐蔽 bug：模板字符串里的正则转义

响应处理器是**以字符串形式**被 `Function()` 求值的（OCS 的机制），
所以正则写在模板字符串里必须用 `\\s`；v5 写成了 `\s`，
求值后变成 `s` → 前缀正则**实际是坏的**（`答案：C` 只是被后面的兜底碰巧救回）。

> 这条与 M19 踩过的坑同类：**字符串里的正则转义**。测试里对 handler 做真实求值才能抓到。

### 9.3 v6 的修法：保守归一化

只在"整段答案明显就是选择题/判断题答案"时才改写，其余**原样返回**：

| 规则 | 条件 |
|---|---|
| 判断题 | 整段（去标点后）**恰好**是极性词：正确/对/√/true… 或 错误/错/不正确/×/false… |
| 判断题+括注 | **以**极性词开头 + 简短括号补充，如 `错误（该说法不成立）` |
| 单选 | 整段**就是**一个字母（可带一层括号）：`A`、`(A)` |
| 多选 | 字母之间**有分隔符**：`A,C`、`A、C`、`A，C` |
| 显式前缀 | **必须带冒号/是**：`答案：X`、`答：X`；且只剥前缀，不改内容 |
| 口语化 | 短句（≤8 字）+ 以单字母结尾 + 含"选/答案/项"：`应该选 D` |
| 其它 | 一律原样返回（**填空 / 主观题 / 多空 / 选项原文**） |

### 9.4 验证

| 项 | 结果 |
|---|---|
| 26 个填空答案的差分 | 只有 2 处被改，且都正确（`(A)`→`A`、`答：2x+1`→`2x+1`）|
| 单元测试 | 164 + **77** + 20 + 30 = **291 项全绿** |
| 产物 | `5.2.1-cxstudy.6`，487,724 bytes |

### 9.5 教训

1. **"提高匹配率"的改动必须同时验证"不误伤其它题型"** —— 我只测了选择题就发布了 v5
2. 响应处理器里的正则要**双反斜杠**（模板字符串），且必须靠**真实求值测试**兜住
3. 归一化要遵守"**不明确就不动**"：无法从响应本身判断题型时，宁可保守
